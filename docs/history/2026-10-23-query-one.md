# Однострочный SQL-путь: проверка 2026-10-23

Тип: `history`. Статус: `historical`. Дата проверки: 2026-10-23.

Снимок этапа после `786fe50`: [исходные данные, probe/runner и hashes](2026-10-23-query-one.json). Актуальная семантика принадлежит [SQL-контракту](../design/sql-gen-product.md#runtime-и-применение); этот отчёт не заменяет его.

## Результат и цена подключения

В Storage добавлен queryOne; PostgreSQLStorage выполняет исходный SQL, получает одну строку через PDO::fetch и вызывает closeCursor в finally. SqlExecutor.fetchOne делегирует этому пути, fetchOneRow преобразует одну строку. Прямой lookup каталога также использует queryOne с прежним SQL по primary key. Путь разработчика — один вызов с SQL/параметрами либо существующий generated query; новые services, flags, SQL rewrites или ORM не добавлены.

Первая строка либо null сохраняют прежнюю семантику SqlExecutor. Метод не проверяет уникальность, не дописывает LIMIT и не сокращает UPDATE/INSERT RETURNING до одной изменённой строки. Ошибки БД остаются StorageException с PDOException/SQLSTATE. Собственные реализации Storage должны добавить queryOne; default fallback через fetchAll не предоставляется. Native prepared statements и соединение продолжают переиспользоваться. БД-чтения помечены impure для PHPStan, поскольку после записи результат может измениться.

Результат по трём целям: прямой SQL-потребитель получает строку без ручного разбора списка; typed execution использует тот же путь; полный PHP-массив не создаётся. Без вызова queryOne остальные query/execute paths сохраняются. Для запроса, уже возвращающего одну строку, не обещается заметного ускорения.

## Короткий CLI-замер

PHP 8.5.9, PostgreSQL 16.15 в уже имеющемся Docker image, Darwin arm64. Fixture — отдельная случайная схема, 20 000 строк, BIGINT primary key и TEXT payload 1024 байта; схема удалена после измерения. Использован обычный buffered PDO с native prepares. Каждый вариант запускается семью отдельными PHP-процессами, один прогрев statement и одно измеренное чтение; порядок 42 процессов перемешан с seed 20261023. В каждой паре SQL и возвращённая первая строка одинаковы.

`legacy` воспроизводит прежний fetchAll → rows[0], `one` — queryOne. Память измеряется после прогрева до проверок/JSON encoding, относительно baseline; в обоих случаях на выходе остаётся только первая строка. Поэтому сравнивается пик временного массива, а не размер итогового возвращаемого значения.

| SQL-сценарий | Пик PHP сверх baseline, legacy / one, bytes | Медиана одного вызова, legacy / one, ms |
| --- | ---: | ---: |
| Lookup по primary key | 1 872 / 1 656 | 0,246 / 0,222 |
| ORDER BY с явным LIMIT 1 | 1 872 / 1 656 | 0,290 / 0,301 |
| ORDER BY без LIMIT, 20 000 строк | 33 648 440 / 1 656 | 42,225 / 24,969 |

Это короткие loopback CLI observations при локальной нагрузке, не HTTP benchmark и не прогноз latency сервиса. Малые различия времени не устанавливают преимущество пути для lookup/LIMIT 1. Подтверждённая ресурсная разница — отсутствие большого Zend-массива для unbounded result; строки и native-буфер PostgreSQL при этом всё ещё могут быть получены целиком.

`closeCursor()` не является гарантией освобождения native PGresult из кешируемого statement: [cursor closer в pdo_pgsql PHP 8.5](https://github.com/php/php-src/blob/PHP-8.5/ext/pdo_pgsql/pgsql_statement.c) сам не очищает этот буфер. Его время жизни связано со следующим исполнением/уничтожением statement. Счётчики PHP не включают native libpq allocations, RSS процесса, БД или сеть; общий bounded memory/устойчивость worker этим этапом не доказаны. Для ограничения возвращаемых БД строк нужен явный LIMIT или уникальный предикат, для больших полей — прикладные пределы.

## Воспроизведение замера

Подготовьте отдельную test database и TEST_DB_HOST/PORT/NAME/USER/PASSWORD, как описано в [инфраструктуре](../development/infrastructure-and-testing.md). Из корня сохраните probe/runner из JSON и выполните runner с уже заданным окружением:

```bash
mkdir -p var
python3 - <<'PY'
import json, pathlib
report = json.loads(pathlib.Path('docs/history/2026-10-23-query-one.json').read_text())
pathlib.Path('var/fetch-one-probe.php').write_text(report['probe_php'])
pathlib.Path('var/measure-fetch-one.py').write_text(report['runner_python'])
PY
python3 var/measure-fetch-one.py
```

Runner создаёт собственную случайную схему, выполняет одинаковые варианты и удаляет именно её в finally. Он использует PHP/Python платформы, ничего не скачивает. Вывод — summaries и `var/fetch-one-measurements.json`. Значения нового запуска могут отличаться.
